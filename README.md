# WEBBOSS — portfolio

Next.js (App Router) + TypeScript implementation of the approved Claude Design
project (`Dawid Bubnow.dc.html`). The design file is the source of truth for
composition, type, spacing, colour and section rhythm; this repo adds the
motion, responsive behaviour and production concerns the static file cannot
express.

## Two names

`site.brand` (**WEBBOSS**) is the studio the site lives under: it owns the
navigation wordmark, the mobile menu anchor, the document title and the
OpenGraph card. `site.name` (**Dawid Bubnow**) is the person: he owns the hero
display type and the About byline. They are never set side by side at equal
weight — About is the one place the relationship is stated outright.

```bash
npm install
npm run dev        # next dev
npm run build      # next build
npm run start      # serve the production build
```

## Deploying

Standard Next.js App Router project at the repository root. Import into Vercel
with **Framework Preset: Next.js** and **Root Directory: repository root** — no
build-command, output-directory or environment overrides are needed.

The page is fully static (`○ Static` in the build output): there are no server
components doing data work, no API routes and no runtime configuration.

`next/image` is deliberately not used. The portfolio ships its own responsive
derivatives — AVIF + WebP at fixed widths, generated by `scripts/images.mjs`
and served from `public/img` through plain `<picture>` elements. That output is
committed, so a clean clone builds without the source artwork present.

### Repository layout

```
app/          layout (metadata, JSON-LD, font preloads) and page
components/   Portfolio.tsx is the single "use client" boundary; everything it
              imports joins the client bundle, so no other file needs the
              directive
hooks/ lib/ data/ styles/
public/       img (generated), fonts (self-hosted woff2), og.jpg, favicon
scripts/      images.mjs, fonts.mjs — one-off generators, output committed
_legacy/      superseded implementations, excluded from the build. Safe to
              delete: rm -rf _legacy
```

## Regenerating assets

Both scripts are one-off generators; their output is committed.

```bash
npm run images           # PNG sources -> responsive AVIF/WebP + data/images.ts
node scripts/fonts.mjs   # re-download the self-hosted woff2 subsets
```

`scripts/images.mjs` reads the approved PNGs and the `captures/` screenshots
from the repo root and writes `public/img` plus a typed manifest, so
`<Picture>`'s srcsets can never drift from what is actually on disk.

## Selected work

The project presentation *is* the technical showcase. `components/Work.tsx`
pins a sticky stage and translates vertical scroll into horizontal travel
across five scenes.

The travel distance is measured (`rail.scrollWidth + paddingRight -
stage.clientWidth`), never assumed — scenes are sized in `vw` and gaps in
`clamp()`, so the real width is the only reliable number, and a flex row's
trailing padding is missing from `scrollWidth`.

Two scroll variables drive the scenes, and the difference matters:

- `--near` — distance from the stage centre. Depth only (scale, image parallax).
- `--in` — how far the scene has entered from the right. Everything that must
  *resolve*: the title reveal, the mask wipe, the hairline. The rail stops
  before the last scene ever reaches the centre, so anything keyed to `--near`
  would stay permanently half-revealed there.

Each scene inherits art direction from the real site through `scene` in
`data/projects.ts` (ground, ink, muted, accent), while the WEBBOSS system keeps
the metadata, type and spacing identical across all five. `layout` picks the
staging: `figure`, `product`, `service`, `portrait`, `warm`.

**Mobile does not scroll-jack.** Scenes become `position: sticky` panels that
cover one another. The desktop captures are 2400×1500, so a 16/10 box shows
each one whole; cropping a site screenshot into a phone-shaped slot leaves an
unreadable fragment.

### Adding a project

Append to `data/projects.ts`, add both captures to `scripts/images.mjs`'s
`JOBS`, and run `npm run images`. The rail's height comes from `--count`.

## Motion

Every scroll-linked effect registers with `src/lib/driver.ts`, which coalesces
scroll, resize and pointer into one `requestAnimationFrame` pass and writes
transforms straight to refs — a scroll frame never causes a React render. Load
entrances are CSS keyframes; nothing else animates.

**Four rules worth knowing before editing the motion:**

1. *Never write a scroll-driven `transform` to the same element that carries an
   entrance keyframe.* The per-frame inline style wins, and the entrance
   silently never runs. The hero splits these across a wrapper and an inner
   element (`.hero__shift` / `.hero__word`, `.hero__mMask` / `.hero__mWord`)
   for exactly this reason. Where an element must own its transform in JS, its
   keyframe animates `clip-path` only (`dbWipe`).
2. *An enter transition needs a frame in the closed state first.* `MobileMenu`
   mounts, paints one frame, then flips to `.menu--open` on a double rAF.
   Applying the class in the same commit as the mount skips the whole
   choreography on the way in — it would only ever animate on close.
3. *Kinetic type travels in from off to the side and settles at exactly 0.*
   `Manifesto` and `DesignCode` both run `settled = ease(clamp((c + 0.55) /
   0.72, 0, 1))`. The window is late on purpose: `c + 1` finishes the move
   before the section is properly on screen, so you never see it. Sections
   carry `overflow-x: clip` (not `hidden` — no scroll container) to absorb the
   travel; because the settled offset is 0, the resting composition can never
   be the thing that gets cut.
4. *Measuring scroll animations needs `scroll-behavior: auto`.* The page sets
   `smooth`, so `window.scrollTo` animates and a short wait lands nowhere near
   the target — a probe will report a frozen animation that is in fact working.
   Every scroll probe injects `html{scroll-behavior:auto !important}` first.
5. *Mobile overrides need the specificity of the rules they override.* The
   per-scene variants are two-class selectors (`.scene--warm .scene__stage`).
   Media queries add no specificity, so the mobile block is written as
   `.work .scene__stage` to match and win on source order.

`prefers-reduced-motion` unregisters the effects entirely rather than running
them at zero amplitude, so the cost goes away with the movement. The contextual
cursor and the magnetic CTA additionally require a fine pointer.

## The hero cutout

`hero-cutout.png` is a matted cutout: 8.9% fully transparent, 53% feathered.
Composited on `#080808` the feathering is imperceptible (the brightest halo
pixel measures 15,11,10 against a ground of 8,8,8), so the figure meets the
page with no rectangle and needs no gradient to fake one.

The reference stood the figure against a lifted `#0c0c0c` panel. With a real
cutout that panel is the only thing left making the portrait look pasted on —
it draws a hard tonal step down the middle of the hero (measurable: `8,8,8` to
`12,12,12` at a single pixel column). `.hero__plate` is therefore `display:
none` and the hero ground is one flat black.

One gradient remains, and it is not hiding an edge: the shot keeps a
motion-blur trail to the left of the figure which is semi-transparent, so where
it crosses BUBNOW it greys the letter instead of occluding it. A ramp over the
left 20% removes the trail only — that region is already near-transparent, so
it produces no visible boundary.
